# Решение проблем с пересылкой писем

## Проблема: Письма не пересылаются автоматически

### Возможные причины:

1. **Автоматический checker не запущен**

   -  Проверьте, что в `.env` установлено: `ENABLE_GMAIL_REPLY_CHECKER=true`
   -  Перезапустите сервер после изменения `.env`

2. **Письмо уже прочитано** (РЕШЕНО)

   -  ~~Автоматический checker обрабатывает только **непрочитанные** письма~~ ✅
      ИСПРАВЛЕНО
   -  Теперь автоматический checker также проверяет прочитанные письма за
      последний час
   -  Если письмо было пропущено, cron-задача обработает его в течение часа
   -  **Ручное решение**: Запустите `node process-all-emails.js [alias]` для
      немедленной обработки

3. **Алиас не найден в заголовках письма**

   -  Письма-ответы (Reply) могут иметь алиас в других заголовках
   -  **Улучшение**: Код теперь проверяет все заголовки (To, Reply-To,
      X-Original-To, Delivered-To, Envelope-To)

4. **Кампания не найдена в MongoDB**

   -  Убедитесь, что кампания с нужным алиасом существует в базе
   -  Проверьте правильность алиаса

5. **Client Email не указан**
   -  Убедитесь, что в кампании указан `clientEmail` или установлен
      `ADMIN_EMAIL` в `.env`

### Улучшения в коде:

1. **Расширенный поиск писем:**

   -  Теперь ищет по `to`, `cc` и содержимому
   -  Находит письма даже если они пришли как ответы

2. **Улучшенное извлечение алиаса:**

   -  Проверяет все заголовки письма
   -  Работает с несколькими адресами в одном поле

3. **Детальное логирование:**

   -  Показывает, в каком заголовке найден алиас
   -  Выводит предупреждения, если алиас не найден

4. **Обработка прочитанных писем (НОВОЕ):**

   -  Автоматический checker теперь также проверяет прочитанные письма за
      последний час
   -  Защита от дубликатов через MongoDB коллекцию `processed_emails`
   -  Письма автоматически удаляются из истории обработки через 24 часа

5. **Cron-задача для резервной обработки (НОВОЕ):**

   -  Запускается каждый час и обрабатывает все письма за последние 24 часа

      `mennekis@gmail.com`
   -  Уведомления отправляются не чаще одного раза в час (защита от спама)

## Проблема: Ошибка "invalid_grant" при проверке ответов

### Автоматическое решение (НОВОЕ):

Система теперь автоматически обрабатывает ошибки истечения токена:

1. **Автоматическое обновление access token:**

   -  При ошибке `invalid_grant` система автоматически пытается обновить access
      token
   -  Если refresh token валиден, токен обновляется и операция повторяется
   -  Работает для всех операций Gmail API (получение писем, пометка как
      прочитанных)

2. **Уведомления администратора:**
   -  Если refresh token истек и не может быть обновлен, система отправляет
      email на `mennekis@gmail.com`
   -  Уведомление содержит:
      -  Детали ошибки
      -  Пошаговые инструкции по исправлению
      -  Время ошибки и информацию о сервере
   -  Уведомления отправляются не чаще одного раза в час

### Ручное решение:

Если автоматическое обновление не помогло (refresh token истек):

1. **Подключитесь к VPS:**

   ```bash
   ssh root@your_vps_ip
   ```

2. **Перейдите в директорию backend:**

   ```bash
   cd /root/sender-app/backend
   ```

3. **Запустите скрипт для получения нового refresh token:**

   ```bash
   node get-refresh-token.js
   ```

4. **Обновите GMAIL_REFRESH_TOKEN в файле .env:**

   ```bash
   nano .env
   # Обновите значение GMAIL_REFRESH_TOKEN
   ```

5. **Перезапустите контейнер:**
   ```bash
   cd /root/sender-app
   docker-compose restart backend
   ```

### Проверка работы автоматического обновления:

1. **Проверьте логи:**

   ```bash
   docker-compose logs --tail=50 backend | grep -i "token\|refresh"
   ```

2. **Ожидаемые сообщения при успешном обновлении:**

   -  `✅ Access token refreshed successfully`
   -  `✅ Token refreshed. Retrying [operation]...`

3. **Ожидаемые сообщения при ошибке refresh token:**
   -  `❌ Refresh token expired or invalid`
   -  `✅ Token error notification sent to mennekis@gmail.com`
