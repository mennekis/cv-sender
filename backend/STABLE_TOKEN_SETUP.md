# Настройка стабильной работы токенов (чтобы не сгорали)

## Проблема: токены истекают за неделю

Токены могут истекать по следующим причинам:

1. ❌ Приложение в тестовом режиме (Testing) - токены истекают быстрее
2. ❌ Refresh token не используется регулярно
3. ❌ Неправильный тип OAuth клиента

## Решение: 3 критических шага

### ✅ Шаг 1: Опубликовать OAuth приложение (КРИТИЧНО!)

**Почему это важно:**

-  В тестовом режиме токены могут истекать через 7 дней неактивности
-  После публикации refresh token работает неограниченно долго (пока не отозван)

**Как сделать:**

1. Откройте
   [OAuth Consent Screen](https://console.cloud.google.com/apis/credentials/consent?project=gmail-forwarder-478218)

2. Проверьте статус вверху страницы:

   -  🟡 **"Testing"** → нужно опубликовать
   -  🟢 **"In production"** → уже опубликовано ✅

3. Если статус "Testing":

   -  Найдите кнопку **"PUBLISH APP"** вверху страницы
   -  Нажмите на неё
   -  Подтвердите публикацию
   -  Дождитесь изменения статуса на "In production"

4. **Важно:** После публикации рекомендуется получить новый refresh token (см.
   Шаг 3)

---

### ✅ Шаг 2: Создать Desktop Application клиент для получения токена

**Почему это важно:**

-  Текущий Web application клиент не поддерживает `your_secret_value`
-  Desktop application клиент нужен для получения токена через скрипт

**Как сделать:**

1. Откройте
   [Credentials](https://console.cloud.google.com/apis/credentials?project=gmail-forwarder-478218)

2. Нажмите **"CREATE CREDENTIALS"** → **"OAuth client ID"**

3. Выберите тип: **"Desktop app"** (Desktop application)

4. Введите имя: "Gmail Sender Desktop Client"

5. Нажмите **"CREATE"**

6. **Скопируйте и сохраните:**

   -  Client ID
   -  Client Secret

7. Обновите `.env` файл (локально или на VPS):
   ```env
   GMAIL_CLIENT_ID=your_gmail_client_id.apps.googleusercontent.com
   GMAIL_CLIENT_SECRET=your_gmail_client_secret
   GMAIL_REDIRECT_URI=your_secret_value
   ```

---

### ✅ Шаг 3: Получить новый refresh token после публикации

**Почему это важно:**

-  Токен, полученный в тестовом режиме, может иметь ограничения
-  Новый токен после публикации будет работать стабильно

**Как сделать:**

1. **Локально:**

   ```bash
   cd /Users/alexey.nikolayenko/Desktop/Experiments/mail-sender/Sender_App2/cv-sender/backend
   node get-refresh-token.js
   ```

2. **Или на VPS:**

   ```bash
   ssh root@your_vps_ip
   cd /root/sender-app/backend
   node get-refresh-token.js
   ```

3. Следуйте инструкциям скрипта:

   -  Откройте URL в браузере
   -  Авторизуйтесь
   -  Скопируйте код
   -  Вставьте код в терминал

4. Скрипт автоматически сохранит новый `GMAIL_REFRESH_TOKEN` в `.env`

5. **Если на VPS:** Обновите `.env` на сервере и перезапустите:
   ```bash
   cd /root/sender-app
   docker-compose restart backend
   ```

## Как работает автоматическое обновление (уже настроено)

Система **уже настроена** для автоматического обновления токенов:

### ✅ Автоматические механизмы:

1. **При каждой проверке email (каждые 5 минут):**

   -  Access token обновляется автоматически
   -  Это поддерживает активность refresh token

2. **Проактивное обновление (каждые 3 дня):**

   -  Система обновляет токен даже если он еще не истек
   -  Это предотвращает истечение refresh token из-за неактивности

3. **Автоматическое восстановление при ошибках:**
   -  Если токен истек, система пытается обновить его автоматически
   -  Если refresh token истек → отправляется уведомление администратору

### 📊 Проверка работы:

```bash
# На VPS - проверка логов
docker-compose logs --tail=100 backend | grep -i "token\|refresh"

# Должны увидеть:
# ✅ Access token refreshed successfully
# ✅ Proactive token refresh completed
# ✅ Email checker started
```

## Если токен все равно истекает

1. Проверьте логи на ошибки:

   ```bash
   docker-compose logs backend | grep -i "invalid_grant\|token expired"
   ```

2. Убедитесь, что приложение опубликовано:

   -  Статус должен быть "In production"

3. Проверьте, что автоматическое обновление работает:

   -  В логах должны быть сообщения об успешном обновлении

4. Если проблема сохраняется:
   -  Получите новый refresh token (см. Шаг 3)
   -  Убедитесь, что используете Desktop application клиент
