# Исправление автоматической обработки писем

## Проблема

Ручной запуск (`process-all-emails.js`) работал корректно и пересылал письма, но
автоматическая обработка не работала - письма, отправленные вчера днем, не были
пересланы на нужный ящик.

## Причина проблемы

Автоматический checker (`gmailReplyService.js`) имел критическую ошибку в
функции `getRecentReadEmails()`:

1. **Ограниченный интервал поиска**: Функция искала прочитанные письма только за
   последний час, а не за последние 24 часа
2. **Пропуск писем**: Если письмо было прочитано более часа назад (но не
   обработано), оно не находилось автоматическим checker'ом
3. **Недостаточная обработка ошибок**: Ошибки при обработке одного письма могли
   остановить обработку остальных

## Что было исправлено

### 1. Исправлен запрос поиска непрочитанных писем

**Проблема:** Сложный запрос с OR не находил письма в Gmail API.

**Было:**

```javascript
const query = `(to:seafarer_@your_sendgrid_api_key OR cc:seafarer_@your_sendgrid_api_key OR seafarer_@your_sendgrid_api_key) after:... is:unread`;
```

**Стало:**

```javascript
const query = `seafarer_ after:... is:unread`;
```

Простой поиск работает надежнее и находит все письма с `seafarer_` в любом
заголовке.

### 2. Увеличен интервал поиска прочитанных писем

**Было:**

```javascript
// Получаем прочитанные письма за последний час
const oneHourAgo = new Date(Date.now() - 60 * 60 * 1000);
maxResults: 20;
```

**Стало:**

```javascript
// Получаем прочитанные письма за последние 24 часа (как в ручном запуске)
const twentyFourHoursAgo = new Date(Date.now() - 24 * 60 * 60 * 1000);
maxResults: 50;
```

### 3. Улучшен поиск прочитанных писем

Используется тот же широкий поиск, что и в ручном запуске:

```javascript
const query = `seafarer_ after:${...} -is:unread`;
```

### 4. Улучшена обработка ошибок

Теперь ошибки при обработке одного письма не останавливают обработку остальных:

-  Каждый вызов `getUnreadEmails()` и `getRecentReadEmails()` обернут в
   try-catch
-  Каждая обработка письма обернута в try-catch
-  Процесс продолжается даже при ошибках

## Как проверить, что исправление работает

### 1. Проверьте, что автоматический checker запущен

На сервере проверьте переменную окружения:

```bash
grep ENABLE_GMAIL_REPLY_CHECKER /root/sender-app/backend/.env
```

Должно быть:

```
ENABLE_GMAIL_REPLY_CHECKER=true
```

### 2. Проверьте логи автоматического checker'а

```bash
# Логи приложения
tail -f /root/sender-app/backend/logs/out.log

# Или логи PM2
pm2 logs seafarer-backend
```

Ищите сообщения:

-  `📧 Checking for new email replies...`
-  `📬 Found X unread email(s)`
-  `📬 Found X recent read email(s) from last 24h`

### 3. Проверьте логи cron-задачи

```bash
tail -f /root/sender-app/backend/logs/cron.log
```

Cron-задача запускается каждый час и обрабатывает все письма за последние 24
часа.

### 4. Ручной тест

Можно запустить тест вручную:

```bash
cd /root/sender-app
docker-compose exec backend node test-email-forward.js
```

## Дополнительные рекомендации

1. **Мониторинг**: Регулярно проверяйте логи, чтобы убедиться, что письма
   обрабатываются
2. **Cron как резерв**: Cron-задача (`process-all-emails-cron.js`) работает как
   дополнительный уровень защиты
3. **Интервал проверки**: Автоматический checker работает каждые 5 минут
   (CHECK_INTERVAL), что достаточно для оперативной обработки

## Файлы, которые были изменены

-  `cv-sender/backend/services/gmailReplyService.js`
   -  Функция `getUnreadEmails()` - упрощен запрос поиска (использует
      `seafarer_` вместо сложного OR)
   -  Функция `getRecentReadEmails()` - увеличен интервал с 1 часа до 24 часов
   -  Функция `checkAndProcessReplies()` - улучшена обработка ошибок
